Keep in mind that I want the code to be as sistematic and possible, meaning changes should preferably consider future mechanics of similar characteristics being implemented and bundled in this base. So random patches to fix specific buffs' mechanics (unless the mechanic is too specific) is not very appreciated.

Additionally, the code must be easier for the programmer (and the user) to review the results and spot errors. Because of that, I created it with the mentality of every mechanic being assigned to either a boolean state (DDS = ON/OFF, mini_nuke_enhanced = ON/OFF, VBTD enhanced = ON/OFF, Mizuki C2 Elemental Buff = ON/OFF, etc) or stacks (buff has this much stacks = integer), etc. This should be printed to the final table if the mechanic is relevant to the setup.

The design philosophy of keeping the architecture systematic (extensible via state-to-buff mapping) and auditable (every mechanic exposed as a tracked state flag or stack count in the timeline table.

Buff data model (see text/Implementation_Backlog.md "Buff architecture"):
buffs.py holds ONLY data. A dynamic (non-constant) effect declares a "basis"
instead of a lambda: "em" (initial EM), "flat_em" (flat EM basis: base + weapon +
artifacts + flat buffs, never percentage shares), "atk" (resolved ATK from the
initial stats) or "talent" (the value is a talent scaling from skill_scalings).
Resolution is value = min(floor + ratio * max(basis - offset, 0), cap) and lives in
stats_calc.evaluate_dynamic_buff. Adding a character/buff should therefore be data
entry (values + basis + target + gate), never a new special case in the resolver.
Effects whose trigger is not implemented yet are listed in buffs.DORMANT and in the
backlog, and smoke_test.py fails if any other catalogue entry is unreachable.

#Weapons
Split in two halves. PERMANENT (base atk, secondary stat, and any description stat that is always on) lives in weapons.py and is folded into the character's initial stats, so it also shows in the card stats. If a description value depends on refinement it is a list [R1..R5]; when the secondary stat is the same stat, both are already merged into one number (see Starcaller's Watch).
BUFFS (anything conditional) are timeline flags + buffs.py values + FLAG_TO_BUFFS descriptors, and they only exist while that weapon is equipped by a selected character.
Weapon labels are resolved with weapons.resolve_weapon_key(), which strips only a trailing "(R<digit>)" so names like "The Widsith (Average)" survive.
A weapon buff's caster is the sentinel "holder:<Weapon Name>": it resolves to the party member equipping it (None when unequipped), which makes the buff holder-only by construction and lets one flag serve several value variants (the unequipped variant is simply skipped).
Per-element DMG bonuses are written element by element (there is no generic elemental_bonus stat) and they are STANDARD DAMAGE ONLY: they never enter stellar or stellar-reaction damage, same as Sucrose's C6 cryo_bonus.

The Widsith (Average)     Buff on taking the field: 10s duration with a 30s cooldown measured from the trigger (re-entering early does not refresh). The 3-way roll is modelled as one third of every outcome at the same time: atk_percent + em + the 7 elemental bonuses.
The Widsith (All EM)      Same trigger/window/cooldown, but the roll always lands on EM so only the full EM value is granted.
Sacrificial Jade         Starts active. More than 10s of CONTINUOUS on-field time removes it; 5s of continuous off-field time brings it back. Grants hp_percent and em.
Sunny Morning Sleep-In    Three independent self windows: stellar swirl -> em for 6s; a standard SKILL hit -> em for 9s; a standard BURST hit -> em for 30s. Only standard damage carries those attack types.
Starcaller's Watch       No buff, just a permanent refinement-dependent EM secondary.

A Thousand Floating Dreams   PERMANENT, party-composition dependent (weapons.py "party_stats" + stats_calc.apply_weapon_party_stats): the holder gains [32..64] em for each of the OTHER members whose element differs from the holder's, and [0.10..0.26] of the HOLDER's element bonus for each other member that shares it (the holder never counts itself). Every other party member also gains a flat [40..48] em. The pass is idempotent so the UI cards and the simulation can both call it.
Wandering Evenstar        A 12s buff every 10s starting at t=0, so there is always a 2s window with two stacks. Holder: [24..48]% of their FLAT EM as atk_flat per stack. Others: 30% of that value. Purely time-based (no trigger event), stack count is derived from t.
Thrilling Tales          The holder's SWAP_OUT arms the buff for the NEXT character to take the field: atk_percent [24..48]% for 10s, 20s cooldown measured from the swap-out. The timeline tracks the target and only flags the window on that character's own hits.
Starsealed Edict         Permanent refinement-keyed crit_dmg (weapons.py) plus two linked buffs: a 20s em window [48..96] opened by the holder's skill CAST (attack_type == SKILL and hit_offset == 0, i.e. the first hit of a skill ability) and refreshed by every new cast; and per-stack em [24..48] where every stellar swirl by ANYONE during the window adds a stack. Refreshing or letting the window expire resets the stacks to 0.
Weapon values are always resolved with the CASTER's refinement, so an R5 weapon buffs an R1 ally with its R5 numbers.

Whitelake Frostfeather      One stack per skill hit (0.1s gain CD), each stack lasting 8s on its own; at 3 stacks a new stack refreshes the OLDEST one. Per stack: atk_percent. At exactly 3 stacks it also grants STELLAR crit DMG (not plain crit DMG), consumed exactly like Mizuki's C6-1 stellar crit.
Finale Of The Deep         A standard skill hit opens a 15s atk_percent window; 10s cooldown measured from the trigger, so later skill hits refresh it.
Azurelight / Aquila Favonia / Sacrificial Bow   Permanents only: refinement atk_percent (Azurelight, Aquila + physical), and base ATK + ER for Sacrificial Bow.
Breezeborne Refrain         Sigils from skill/burst damage (0.03s CD, they never expire). At 3 the sigils reset, the whole party gains stellar_bonus for 12s and no sigils are gained during that buff.
Elegy for the End           Sigils from skill/burst damage (0.2s CD). At 4 they reset, the whole party gains atk_percent + em for 12s and no sigils are gained for 20s from the trigger. Also a permanent refinement em.
New Bough                   A skill hit opens (or refreshes) a 12s window; ANY damage hit by the holder inside it grants a stack (max 3), at most one per second, with the opening skill hit counting as the first stack.
Silverdawn                  Skill/burst damage opens a 6s self window (atk_percent + STELLAR crit DMG). Every stellar swirl the holder triggers, or stellar hit they deal, extends it by 3s (0.1s CD, max 8 extensions => 30s cap).

#Artifacts
Permanent set stats live in artifacts.py. The common pools (hp/atk/def percent + flat, em, crit, er, physical/element bonuses) are composed explicitly from character + weapon + artifact MAINS + substats, and EVERY other artifact-set stat (element bonuses, stellar_bonus, stellar_crit_*, skill/burst/charged/normal_bonus, crit_*, er, ...) is folded generically by build_initial_stats. So a set may grant any stat key.
Those values stay in the character's initial_stats, are exported in the party .json (snapshot_party -> initial_stats) and feed every snapshot/damage calculation, but they are NOT printed on the character card (the card keeps HP/ATK/DEF/EM, CR or CV + CD, ER and the element DMG lines).
Element DMG bonuses and attack-type DMG bonuses (normal/charged/plunging/skill/burst) are STANDARD DAMAGE ONLY. Stellar damage reads em + stellar_bonus (+ stellar_crit_rate/dmg on crit); stellar reactions additionally use the contributor's em / crit / stellar crit.
Conditional or temporary set effects stay as timeline flags + buffs.py entries + FLAG_TO_BUFFS descriptors, exactly like HotF / VV / Instructor.
